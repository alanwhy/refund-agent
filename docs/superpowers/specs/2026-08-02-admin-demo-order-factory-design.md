# 管理员演示订单工厂设计

## 1. 背景与目标

当前系统只有 seed 生成的固定订单。用户虽然能验证退款 Agent、人工审批和技术异常的局部路径，
但无法从零完成“管理员创建客户订单 → 客户申请退款 → 系统自动处理或转交人工”的完整演示。

本功能在管理员“全部订单”页面增加受控的演示订单创建能力。管理员选择现有客户、商品名称和
预设场景，服务端生成持久化订单。订单创建本身不启动售后流程；管理员需要手动退出并使用对应
客户账号，在“售后对话”中输入新订单号发起退款。

本功能仅用于本地演示数据，不建设通用订单管理、客户管理或真实电商下单系统。

## 2. 核心原则

1. 只有管理员可以创建演示订单。
2. 前端选择业务场景，不能直接控制金额、风控标记或支付行为等内部字段。
3. 场景到订单字段的映射由服务端固定，确保演示结果可预测。
4. 创建订单和创建退款工单是两个独立动作。
5. 新订单永久保存在当前 PostgreSQL 数据卷中，直到用户显式清空 Docker volume。
6. 创建接口使用请求 ID 去重，避免重复点击生成多笔订单。

## 3. 用户流程

### 3.1 管理员创建订单

1. 管理员登录并打开“全部订单”。
2. 点击页面右上角“新建测试订单”。
3. 从现有有效客户账号中选择订单归属客户。
4. 填写商品名称。
5. 选择一个预设场景，并阅读该场景的预期流程说明。
6. 提交后，服务端生成唯一订单号并持久化订单。
7. 页面关闭表单、刷新订单列表并突出显示新订单号。

创建成功后只展示订单号和归属客户，不提供自动切换身份或“代客户退款”功能。管理员自行退出，
使用所选客户的邮箱登录并提交退款申请，以保持角色边界真实可见。登录页选择“客户入口”后允许
填写客户邮箱，默认仍为 `customer@example.com`；演示环境密码保持 `Demo123!`。

### 3.2 客户发起退款

客户登录后可以在“我的订单”看到新订单，然后在“售后对话”中使用该订单号申请退款。此时才
创建 Ticket 并启动 Agent。后续行为由既有确定性政策、风险和支付逻辑决定。

## 4. 预设场景

请求中的 `scenario` 仅允许下列枚举值：

| 场景 | 服务端订单字段 | 预期退款路径 |
| --- | --- | --- |
| `AUTO_REFUND` | 金额 ¥399，无风控标记，支付成功 | 自动退款完成 |
| `AMOUNT_APPROVAL` | 金额 ¥699，无风控标记，支付成功 | 金额超过 ¥500，进入退款审批 |
| `RISK_APPROVAL` | 金额 ¥199，带风控标记，支付成功 | 命中风险规则，进入退款审批 |
| `PAYMENT_UNKNOWN` | 金额 ¥299，无风控标记，支付结果未知 | 进入技术异常队列，不自动重试支付 |

所有演示订单创建时均为 `DELIVERED`，签收时间设置为创建时间前两天，确保落在当前七天无理由
退款政策的有效期内。场景字段映射集中在服务端的单一配置中，API、测试和文档不分别维护数值。

## 5. 后端设计

### 5.1 客户选择接口

新增：

```http
GET /api/demo/customers
```

仅管理员可访问。返回有效且角色为 `CUSTOMER` 的用户摘要：`id`、`display_name`、`email`。
接口不返回密码哈希、账户内部状态或客户订单数据。

### 5.2 创建订单接口

新增：

```http
POST /api/demo/orders
```

请求：

```json
{
  "customer_id": "customer-id",
  "product_name": "演示商品",
  "scenario": "AUTO_REFUND",
  "request_id": "client-generated-uuid"
}
```

约束：

- `product_name` 去除首尾空格后长度为 2–100 个字符；
- `customer_id` 必须指向有效的 CUSTOMER 用户；
- `scenario` 必须是受支持枚举；
- 不接受 `amount`、`fraud_flag`、`payment_behavior`、`status` 或 `delivered_at`；
- 非管理员请求返回 403；无效客户或场景返回 422。

服务端生成格式为 `ORD-DEMO-YYYYMMDD-XXXXXX` 的订单号，其中随机后缀使用安全随机值。该格式
满足 Agent 的 `^ORD-[A-Z0-9-]+$` 订单号 Schema。数据库唯一约束是最终防线；极小概率冲突时
服务端最多重新生成 3 次，仍冲突则返回受控 503。

首次创建返回 HTTP 201；幂等重放返回 HTTP 200。响应为
`{ "order": <管理员订单摘要>, "replayed": <bool> }`，订单摘要包括新订单号、客户姓名、客户
邮箱和订单业务字段。现有管理员 `OrderView` 相应增加 `customer_email`；客户和审核员响应中该
字段始终为 null。

### 5.3 幂等与数据模型

新增专用 `DemoOrderCreation` 记录，字段定义为：

- `id`
- 唯一 `request_id`
- 唯一 `order_id`
- `created_by`
- `scenario`
- `created_at`

服务端在一个数据库事务内创建 Order 和 DemoOrderCreation。相同管理员使用相同 request ID 重试
时返回第一次创建的订单，不生成第二笔。其他管理员复用该 request ID 也返回同一已创建资源，
因为 request ID 是全局幂等键；响应不会扩大调用者原有的管理员权限。

不在 Order 表增加 `scenario`。Agent 仍只读取订单金额、风控标记和支付行为，避免演示概念进入
正式退款规则。

## 6. 前端设计

“全部订单”页右上角在订单数量旁增加“新建测试订单”按钮，仅 ADMIN 渲染。点击后打开同页
表单面板，包含：

- 客户选择：显示姓名与邮箱；
- 商品名称输入；
- 四个场景单选项；
- 当前场景的金额、触发条件和预期流程说明；
- “创建订单”和“取消”操作。

提交期间禁用重复操作。前端为每次新建意图生成一个 request ID；网络失败后再次提交沿用该 ID，
创建成功或取消后才清除。

成功后：

1. 关闭表单；
2. 刷新列表；
3. 新订单行短暂突出显示；
4. 页面顶部显示“测试订单 ORD-DEMO-… 已创建，请使用 customer@example.com 发起退款”，其中
   邮箱替换为所选客户的真实邮箱。

失败时保留客户、商品和场景选择，并显示服务端的明确错误。审核员和客户既看不到入口，也不能
通过手动调用接口创建订单。登录页在选择客户入口后显示可编辑邮箱输入框，使管理员能够按创建
结果中的邮箱切换到对应的既有客户；审批员和管理员入口继续使用固定演示邮箱。

## 7. 权限与安全边界

- 客户列表和订单创建接口都使用后端 ADMIN 角色依赖；
- 创建结果仍受现有订单读取权限约束：客户只能看到自己的订单，审核员不会在审批发生前看到它；
- 创建订单不会创建 Ticket、ApprovalTask、ManualReviewTask 或 RefundRequest；
- 场景只改变本地 Mock 订单字段，不接触外部订单、支付或客户系统；
- 审计记录 `demo_order.created`，保存订单 ID、场景、客户 ID 和创建管理员，不记录敏感数据；
- 演示订单不提供删除接口，避免出现退款工单引用已删除订单的情况。

## 8. 错误处理

- 客户不存在、已停用或角色不是 CUSTOMER：422，提示重新选择客户；
- 商品名无效或场景不支持：422；
- 相同 request ID：HTTP 200 返回既有订单，`replayed=true`；
- 订单号连续冲突：503，提示稍后重试；
- 数据库事务失败：不保留半成品 Order 或 DemoOrderCreation；
- 前端刷新列表失败但创建成功：保留成功订单号提示，并提供“刷新订单列表”操作。

## 9. 测试与验收

### 9.1 后端自动化测试

- 管理员能读取有效客户列表；客户和审核员返回 403；
- 管理员能创建四种场景订单，内部字段映射正确；
- 无效客户、非客户用户、无效场景和非法额外字段被拒绝；
- 相同 request ID 重放只创建一笔订单；
- 批量创建的订单号保持唯一；
- 创建动作不生成工单、审批、异常或退款记录；
- 审计事件不包含敏感字段；
- 四种订单随后进入现有 Agent 后分别到达自动完成、金额审批、风险审批和支付异常路径。

### 9.2 前端自动化测试

- 只有管理员看到“新建测试订单”；
- 表单能加载并选择现有客户；
- 四个场景显示正确的预期流程；
- 提交成功刷新列表并突出新订单；
- 提交失败保留表单值；
- 重试沿用原 request ID；
- 客户入口可填写创建结果提示的客户邮箱；
- 客户和审核员订单页面行为不变。

### 9.3 浏览器验收

1. 管理员分别创建四种测试订单；
2. 客户登录后在“我的订单”看到对应订单；
3. 客户对四笔订单发起退款；
4. 自动退款直接完成；
5. 金额审批和风控审批出现在审核员队列，批准后完成；
6. 支付未知只出现在异常处理队列，不重复支付；
7. 管理员订单页能查看四笔订单与其最新关联状态。

## 10. 非目标

- 新建或编辑客户账号；
- 客户自助下单；
- 管理员模拟登录为客户；
- 自由编辑金额、风控、支付或订单状态；
- 删除、修改或批量导入订单；
- 接入真实订单中心、库存、发货或支付系统。
